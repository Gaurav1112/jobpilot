# jobpilot v1 Daily Product Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development.
> Steps use checkbox (`- [ ]`) syntax.
>
> **Plan style note.** This plan is far larger than the kernel plan. Each task fixes files,
> interfaces, exact values and test cases; the implementer writes the code test-first.

**Goal:** A local, scheduled, LLM-free pipeline that fetches remote-from-India jobs, filters
and scores them deterministically, and builds a grounded per-job resume and cover letter. It
shows everything on a local dashboard.

**Architecture:** New agents, built on the existing kernel (`src/kernel`), live under
`src/app/`. Each agent has one contract. The pipeline wiring lives in
`src/app/pipeline.ts`, and a projector writes run outputs to app tables. The Hono dashboard
reads those tables.

**Tech stack:** TypeScript on Node 24 (ESM, strict), zod 4.6.5, better-sqlite3, vitest,
commander, and these new pinned dependencies:

| Package | Version |
|---|---|
| `yaml` | 2.9.1 |
| `hono` | 4.13.13 |
| `@hono/node-server` | 2.1.4 |
| `docx` | 9.9.0 |
| `pdfkit` | 0.20.2 |
| `@types/pdfkit` | latest 0.x |
| `htmx.org` | 2.x, vendored file |

Spec: `docs/superpowers/specs/2026-10-09-jobpilot-v1-daily-design.md` (read it; it is binding).

## Global Constraints

- Run scripts with `node --run <script>`, never `pnpm <script>`. Use pnpm only for
  `pnpm add` / `pnpm install`.
- Node ≥ 24. ESM imports end in `.js`. TypeScript strict. No `any` without a comment saying why.
- **No language-model call anywhere in v1.** No agent declares `capabilities.llm`.
- Every agent is created with `defineContract` and `defineAgent`.
  - The description is at least 10 characters and contains no word "and".
  - One skill, one output type.
  - `kind` is `deterministic`, or `io` for the source fetchers.
- **The engine holds no personal data.**
  - Tests use `tests/fixtures/pack/`, a fictional candidate named "Asha Rao" whose employers
    are fictional.
  - The real pack lives only in `~/.jobpilot/pack/` (`JOBPILOT_HOME` overrides `~/.jobpilot`).
- **Forbidden-term rule.** The name of the user's current client company must never appear
  in:
  - any file under `src/`, `tests/` or `docs/`;
  - any generated output.

  The name lives only in the user's `~/.jobpilot/pack/naming.yaml` `forbiddenTerms` (and in
  source files outside the repo). Never write it anywhere, not even in a test. A test
  enforces the rule: `tests/forbidden-terms.test.ts` loads `forbiddenTerms` from
  `$JOBPILOT_HOME/pack/naming.yaml` (or `~/.jobpilot/pack/naming.yaml`) when that file
  exists, and skips with a message otherwise. It then scans `src`, `tests` and `docs`
  case-insensitively. Add it in Task 2.
- The comp floor is base salary only. Equity, RSU, bonus and total comp are never counted.
- LinkedIn is never fetched. No anti-bot evasion. The user-agent is honest:
  `jobpilot/0.1 (+local)`.
- Every commit message ends with this trailer:
  `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`
- Work on branch `v1-daily`. Never push.
- `node --run verify` stays green after every task. Before the dashboard has an eval,
  `verify` still runs the demo evals.
- Determinism:
  - no `Date.now()` or `Math.random()` in agents; use `ctx.clock`;
  - output order is sorted by a stable key;
  - documents get fixed metadata (creation date = the posting's `firstSeen` date passed in
    the plan, not now).

### Task 1: Kernel extensions (spec §4)

**Files:**
- Modify: `src/kernel/contract.ts`, `src/kernel/broker.ts`, `src/kernel/executor.ts`,
  `src/kernel/memo.ts`, `src/kernel/supervisor.ts`, `src/kernel/policy.ts`,
  `src/kernel/guardrails/index.ts`, `src/kernel/providers.ts`, `src/evals/runner.ts`,
  `src/demo/kernel.ts`
- Test: extend `tests/kernel/{contract,broker,executor,supervisor,policy}.test.ts` and
  `tests/evals/evals.test.ts`

**Interfaces produced:**
- `Capabilities.pack?: true`. The `AgentContext.pack?: Readonly<unknown>` field is present
  only when the contract declares `capabilities.pack`, and it is deep-frozen.
- `SupervisorDeps.pack?: unknown` and `SupervisorDeps.packHash?: string` (default `'none'`).
  `ExecutorDeps` gets the same.
- `computeStepKey(contract, input, policyHash, packHash = 'none')`. `packHash` is included in
  the hashed object **only when the contract declares `capabilities.pack`**, so a pack edit
  re-runs only the agents that read the pack.
- `GuardrailContext.pack?: Readonly<unknown>` (the same frozen object, always passed when
  present).
- `HttpTool.getJson(url): Promise<{ status: number; json: unknown }>`. Invalid JSON →
  `KernelError('invalid_output', ...)`. `getText` and `getJson` both:
  - send headers `{ accept: 'application/json, text/plain;q=0.8, */*;q=0.1',
    'user-agent': 'jobpilot/0.1 (+local)' }`;
  - enforce `policy.maxResponseBytes` (default 5_242_880) by reading the body and throwing
    `KernelError('invalid_output', 'response exceeds N bytes')` past the cap;
  - enforce `policy.minHostIntervalMs` (default 1000) per host. The broker keeps a
    `lastRequestAt: Map<host, ms>` shared by all contexts of one supervisor; it is passed in
    `IssueArgs.hostPacer`, an object with `wait(host): Promise<void>` built on the injected
    `sleep` and `clock`.
- `FetchLike` init gains `headers: Record<string,string>`. Update `nodeFetch`.
- `Policy.maxResponseBytes: number` and `Policy.minHostIntervalMs: number` in
  `PRODUCT_POLICY_V1`. In `UserPolicy`, both may only tighten:
  - `maxResponseBytes` may only go lower;
  - `minHostIntervalMs` may only go higher.

  Add both to `mergePolicy` monotonic checks.
- Strict contract meta-schema: `defineContract` rejects unknown top-level keys
  (`Meta.strict()`; confirm `capabilities` is strict and accepts `pack`).
- Spend per attempt: the executor records each attempt's spend in the step row's attempts
  detail before the retry sleep (follow the existing store API). Add a test: an agent that
  spends then fails, then succeeds → the step's recorded spend equals the sum of both
  attempts, even if the process is "crashed" via the `afterStep` hook in between.
- Evals forced offline: `runEval` ignores the passed `providers.fetch` and uses one that
  throws `KernelError('policy_denied','evals are offline')`.
- Tracker `keyOf` throwing → the step is quarantined with verdict `G-TRACKER`. Add a test and
  a doc comment on `Tracker.keyOf`.

**Tests (each a failing test first):**
- A pack-reading agent: its step key changes when `packHash` changes. A non-pack agent's key
  does not change.
- `ctx.pack` is undefined without the capability. Mutating `ctx.pack` throws (frozen).
- `getJson` parses JSON. Bad JSON → `invalid_output`. Body over the cap → `invalid_output`.
- Two requests to the same host within one run → the second waits ≥ `minHostIntervalMs`
  (assert via a fake sleep recorder).
- Headers are sent (assert the fake fetch's init).
- `defineContract({... , bogus: 1})` throws.
- A user policy that raises `maxResponseBytes` or lowers `minHostIntervalMs` → `PolicyViolation`.
- An eval agent attempting HTTP gets `policy_denied`.

**Commit:** `feat(kernel): pack capability, JSON HTTP with size cap and host pacing, strict contracts, per-attempt spend, offline evals`

### Task 5b: Career-page source with Playwright (user request: scan complete pages)

**Why:** some employers publish jobs only on their own career site (Workday, custom pages), with no
public JSON API. A real browser renders those pages fully, including JavaScript-built listings.

**Files:**
- Modify: `src/kernel/contract.ts`, `src/kernel/broker.ts`, `src/kernel/providers.ts`, `src/kernel/policy.ts`
- Create: `src/app/agents/sources/careers.ts`, `src/app/browser/playwright-provider.ts`
- Test: `tests/kernel/browser.test.ts`, `tests/app/careers.test.ts`, local HTML fixtures under
  `tests/fixtures/careers/`, served by a tiny `node:http` server in the test

**Kernel capability `browser`** (spec §16.1 row 4, the read-only subset):
- Contracts declare `capabilities.browser: { maxPages: number }` together with exact-host `egress`.
- `ctx.browser.render(url): Promise<{ status: number; finalUrl: string; html: string; text: string; jsonLd: unknown[] }>`.
- The provider interface is `BrowserProvider` in `providers.ts`, so tests use a fake.
- The real provider:
  - uses the `playwright` package (`pnpm add playwright@1.64.0`, chromium already cached locally);
  - launches headless chromium with a fresh context per step;
  - sets the user-agent to the honest `jobpilot/0.1 (+local)`;
  - sets the same `accept` header as `HTTP_HEADERS`;
  - blocks images, fonts and media;
  - waits for `networkidle`, capped at 20 s;
  - keeps no cookies or storage between steps;
  - never fills forms or submits anything;
  - clicks nothing except same-host links that the agent passes to `render` itself.
- Rules the broker enforces:
  - https only;
  - the URL host and `finalUrl` host must both be in `egress` (a redirect to another host is a policy denial);
  - the per-host pacing is shared with `http`, and `policy.minBrowserIntervalMs` (default 10_000, tighten-only) applies;
  - the page budget is `maxPages` per step;
  - the response size cap applies to `html`.
- Challenge stop: a CAPTCHA or bot wall (status 403/429, or html matching
  `/captcha|cf-challenge|are you a robot|access denied/i`) → `KernelError('challenged', ...)`. `challenged` is a
  new non-retryable error code. No retry, no evasion, ever. There is no stealth plugin, proxy, fingerprint or
  user-agent override, and a test asserts that none of these options exist on the capability.
- `policy.deniedEgressHosts` in the product policy gains `linkedin.com`, `naukri.com`, `indeed.com` and
  `glassdoor.com`. The browser must refuse them even if a contract lists them.

**Agent `src-careers`** (kind `io`, team `sourcing`):
- Watchlist entries gain `ats: 'careers'` with `listUrl` (https) and an optional `linkPattern` (regex source,
  compiled through `compileRoleDeny`'s safety checker; reuse the same helper with a neutral name).
- Pack schema update: `WatchEntry.ats` adds `'careers'`. `slug` is a kebab id. `listUrl` is required when `ats` is
  `careers`. Egress for this agent is computed per entry: the contract's `egress` is the list of watchlist
  careers hosts, built when the pipeline is compiled. Document this, and keep it exact-host.
- It consumes `DiscoveryRequest@1` where `ats === 'careers'` and `slug` is the entry slug. Other requests → `[]`.
- Steps:
  1. Render `listUrl`.
  2. Collect job links: same-host anchors matching `linkPattern`, or by default anchors whose path contains
     `/job`, `/jobs/`, `/careers/` or `/position`. Deduplicate and sort them, then cap at `maxPages - 1`.
  3. Render each link and extract the posting.
     - **JSON-LD.** Use the JSON-LD `JobPosting` when present: title, `description` (HTML), `datePosted`,
       `employmentType`, `jobLocationType` (`TELECOMMUTE` = remote), `applicantLocationRequirements`,
       `jobLocation`, `baseSalary`.
     - **Fallback.** Otherwise use the `<h1>` as the title and the page's main text, with the `text` capped
       at 50 KB.
  4. Emit `RawPosting@1` with `source: 'careers'`, `sourceId` = sha256 of the canonical job URL (no query string
     or fragment) as 16 hex characters, `raw` = `{url, jsonLd | null, title, text}`. The timestamps inside
     JSON-LD stay, because they are content.
- If there are more links than `maxPages - 1` → `KernelError('invalid_output', 'careers <slug>: N job links exceed page budget')`.
  This is loud, not a partial result. `maxPages` defaults to 60, and the timeout is
  `maxPages × (minBrowserIntervalMs + 20 s)`.
- The normalizer (Task 6) maps careers RawPostings:
  - JSON-LD `TELECOMMUTE` plus applicant requirements are mapped to `remote.structured` / `countries`;
  - `baseSalary` is mapped to comp with `basis: 'base'`;
  - `employmentType` is mapped as is.

**Tests:**
- Fake-provider unit tests: egress denial, a redirect to another host is denied, a challenge →
  `challenged` (not retried), the page budget, and a test that the capability exposes no stealth or proxy options.
- A real-chromium test against the local `node:http` fixture server:
  - one listing page whose job links are injected by JavaScript after load, to prove full rendering;
  - two job pages, one with JSON-LD and one without;
  - one challenge page.

  Skip it with a clear message when chromium is not installed.

**Commit:** `feat(sources): read-only Playwright career-page source with challenge stop`

### Task 6: Normalizer

**Files:**
- Create: `src/app/agents/normalizer.ts`, `src/app/text/html.ts`, `src/app/text/norm.ts`
- Test: `tests/app/normalizer.test.ts`

**Behaviour:** one function per source maps `raw` to `Posting`.

- **html.ts:** `htmlToText` decodes entities (named and numeric), turns block tags (`p`,
  `div`, `li`, `br`, `h1`–`h6`, `tr`) into newlines and prefixes `li` with `- `, strips all
  other tags, collapses spaces, and allows at most 2 newlines in a row. Greenhouse `content`
  is HTML-escaped HTML, so decode first and then strip.
- **norm.ts:**
  - `normTitle`: lowercase; collapse whitespace; strip the `(m/f/d)` / `(f/m/x)` gender
    suffix and trailing location parentheses `(Remote|India|...)`.
  - `normLocation`.
  - `jobKey = sha256(company.toLowerCase()|normTitle|normLocation).slice(0,16)`.
- **remote.structured:**
  - Lever `workplaceType` (`remote` / `hybrid` / `onsite` / `unspecified` → null);
  - Ashby `isRemote` / `workplaceType`;
  - Greenhouse: null (text only).
- **countries:** ISO-like lowercase names extracted from location text by a fixed list
  (india, united states, us, usa, canada, uk, united kingdom, germany, ...; worldwide →
  `['worldwide']`, apac → `['apac']`, emea, europe, americas, latam).
- **employmentType:** structured when available (Lever `categories.commitment`, Ashby
  `employmentType`), else null.
- **comp:**
  - Ashby compensation summary components and Lever `salaryRange` (min, max, currency,
    interval) are converted to yearly. They are `basis: 'base'` when the component is
    salary, `'unknown'` otherwise.
  - Else `parseComp(descriptionText)`, but only on lines that mention salary, base, CTC, LPA,
    compensation or pay. These are `basis: 'unknown'` unless the line contains "base".
- **yearsRequired:** the max of the regex matches `(\d{1,2})\+?\s*(?:years|yrs)` inside
  sentences containing "experience". It is null when there is no match, and values above 30
  are ignored.

**Carried from Tasks 5 and 5b:**
- Map `careers` RawPostings (`raw = {url, jsonLd|null, title, text}`; JSON-LD `JobPosting` fields per Task 5b).
- An impossible or unparseable `postedAt` becomes null.
- Sources and their raw shapes: greenhouse, lever, ashby, himalayas, jobicy and careers (see `src/app/agents/sources/*.ts` doc comments for dropped fields).
- Add a plausibility minimum for parsed comp: below ₹1 LPA per year after conversion means not comp, so null.

**Tests:**
