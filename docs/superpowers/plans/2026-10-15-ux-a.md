# jobpilot UX Upgrade Phase A Implementation Plan: safety net and quick wins

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.
>
> **Plan style (same as the v1, freelance, career-sites and profiles plans):** each task fixes files, interfaces, exact
> values and test cases; the implementer writes the code test-first (failing test → run → minimal code → run →
> commit). The spec is binding: `docs/superpowers/specs/2026-10-15-jobpilot-ux-upgrade-design.md`. Sections 1–2 of the
> spec (decisions U1–U10, amendments 1–16) win over its section D. This plan covers **Phase A only** (spec §D9,
> items A0–A14).

**Goal:** before any redesign, put a safety net under the dashboard (golden HTML per route, a perf gate on every route
measured from a cold process, a 400 px no-sideways-scroll check on every page, browser suites that fail instead of
skipping). Then ship the fifteen quick wins of Phase A: template, copy and CSS changes, plus the small server changes
they need, with no new table and no migration.

**Architecture:**
- Everything stays server-rendered HTML from the escaping `html` tag (`src/app/web/html.ts`). htmx and `app.js` only
  enhance. No new dependency, no build step, no new static file.
- One fictional fixture home (`tests/support/web-fixture.ts`) feeds the golden snapshots, the 400 px browser check and
  the before/after screenshots, so all three always see the same pages.
- One triage module (`src/app/triage.ts`) holds the U9 rules (the 7-day "To decide" window, the 5-day follow-up) as
  pure functions plus the SQL fragment, used by the store and the views.
- The perf gate keeps its large synthetic DB, which gains review gigs, companies and skipped hosts, and gains a
  cold-process measurement (amendment 2): a dashboard started with `warmOnStart` answers its first request on every
  route within 150 ms.

**Tech stack:** TypeScript on Node 24 (ESM, strict), hono, better-sqlite3, vitest 5 (`toMatchFileSnapshot`),
playwright (already pinned, Chromium only). **No new dependencies.**

## Decisions this plan makes (spec ambiguities resolved)

1. **Base.** Phase A is planned against `freelance-v2 @ 420b721` (freelance-boost + freelance-v2 + sleep-safe), which
   merges to `main` tonight. Every `file:line` below is at that commit. If `main` differs from it in `src/app/web/` or
   `tests/app/web*`, Task 0 stops and reports instead of guessing.
2. **"Fresh" (amendment 2)** means a new process (code not loaded) with a warm OS file cache. `createDashboard` gains
   `warmOnStart` (on in `serveDashboard`), which opens the shared connection and runs every page's queries once at
   startup. The gate measures each route as the first request of a new child process. The existing in-process "fresh
   connection" numbers stay as they are.
3. **The one perf exception that stays:** `GET /runs` *right after a run* walks that run's new audit events (50,000
   on the synthetic DB, budget `RUNS_AFTER_RUN_MS = 500`, `tests/perf/budget.perf.ts:38`). That is the audit check,
   not page rendering, and moving it off the request path changes the audit design (Phase B10, Runs verdict-first).
   Every other route, fresh and warm, is held to 150 ms.
4. **Routes already over budget when A0 lands** (Review: 110–373 ms in the panel's measurements; Companies with 781
   skipped hosts, unmeasured) get a temporary entry in `KNOWN_SLOW` (Task 5). The task that fixes the route (Task 19
   for Review, Task 20 for Companies) deletes the entry first, which is its failing test.
5. **Browsers fail by default.** A browser suite whose Chromium cannot start fails at collection with an install hint.
   `JOBPILOT_ALLOW_NO_BROWSER=1` is the only way to skip, and it prints a warning. This is stricter than D8's
   `JOBPILOT_REQUIRE_BROWSER=1` (the default is now "required"), so `node --run verify` needs no extra variable.
6. **Brittle tests (amendment 1, D8).** Only the exact-markup assertions that Phase A would break, plus their direct
   neighbours, move to text or structural assertions (Task 7, list there). Security and escaping assertions stay
   exact. The rest of the ~325 `toContain` checks stay until Phase B1, page by page.
7. **U9 in Phase A.** `src/app/triage.ts` holds `TO_DECIDE_DAYS = 7` and `FOLLOW_UP_DAYS = 5` and the one "To decide"
   predicate (TS + SQL). Phase A uses it for the Jobs lede count (A1) and the "Follow-up due" mark on applied rows
   (A14). `next_followup` arrives with B7; until then the formula `next_followup ?? applied_at + 5 d` has no
   `next_followup`, and the function takes it as an argument that callers pass as `null`.
8. **A1 default status.** Without a `status` parameter the list shows every status except Not for me (`skipped`) and
   Not selected (`rejected`), and the Status checkboxes show that default ticked, exactly as the band default works
   today. The lede says they are hidden and links to them. No count is shown for them: that would add a list
   statement, which `tests/app/indexes.test.ts:102-125` pins at four.
9. **A1 sort.** Eligibility tier (eligible = Pay ≥ minimum or Pay not listed; then Check first = review; then Below
   minimum; then Not a match) → fit descending (unscored last) → INR pay descending (not disclosed last) → newest
   first seen → job key. The page size stays 100 (50 rows is B5).
10. **A4 "New".** The per-row sentence goes. A row gets a dot (`●`, with hidden text "New") only when some, not all,
    listed rows are new; the lede says "N new since your last visit" only then. The visit cookie stays until B5.
11. **A5 exception pill priority** (at most one per row, first match wins): Documents blocked → Documents out of date →
    Documents missing → Check before applying (review verdict) → Contract (B2B) → Office: <city> → Pay not listed →
    Pay under your minimum → Not a match. Status is not an exception: it keeps its own pill, and To do (`new`) has
    none. Colours follow amendment 6: only blocked is critical, the "you decide" ones are warn, the rest neutral.
12. **A6 "gig hint labels"** means the gig facts line gets visible labels ("Hours: …", "Overlap: …", "Bids: 7"), and
    the dashboard's " - " joins become a real dash ("rate unknown – fixed budget $750"), per the §6.3 rule.
13. **A6 number grouping.** Counts and INR use en-IN grouping (`groupIndian`, so 570418 → 5,70,418). Dollar amounts
    keep their own grouping and compact style ("$139k–235k"), because they are a foreign currency shown as posted.
14. **A7** adds a visible "fit" caption and the hidden "Fit score 84 out of 100" (the scorer clamps to 0..100,
    `src/app/agents/scorer-lexicon.ts:73`). No tier words and no score change (U5 is Phase B).
15. **A8 next-row redirect (amendment 9).** A list row links to `/jobs/<key>?from=<list URL>&next=<next row key>`.
    When a status set on the job page without JS takes the job out of the list it came from, the 303 goes to
    `<list URL>#job-<next>`; otherwise it returns to the job page as today. The htmx swap is unchanged. `from` is
    accepted only as the jobs list path `/` with a query string.
16. **A2 previews** render closed everywhere (amendment 3 wins over D4.3's "open on desktop") with `loading="lazy"`.
    They stay white through a serve-time `color-scheme: light` override injected into the preview HTML response; the
    HTML, PDF and DOCX files on disk are never changed (daily-identity). Provenance moves out of hover into a visible
    "Facts these documents cite" list beside the previews.
17. **A9 skipped hosts** move to the paged sub-route `/companies/skipped?page=N` (50 per page). Amendment 2 names
    `/system/sources/skipped`; `/system` arrives in B10, which redirects this route there. "Deferred this week" is
    renamed "Skipped this week" here, because the new summary line uses the word.
18. **A3 landing.** `/freelance` without `tab=` opens the first non-empty of Contracts (rows or Contract roles), Gigs,
    Review, in that order, else Contracts. The truthful empty state links to `?tab=<tab>&show=hidden`, a new paged view
    of the gigs that tab left out (below the fit floor, not eligible, not scored).
19. **A11** puts the audit text in `<details>` closed (amendment 3). A broken chain keeps its critical banner, so it
    is never hidden.
20. **A12 banners.** Warn and info banners become `role="status"`; only critical banners keep `role="alert"` (D7
    4.1.3).
21. **A14** shows "Applied 27 days ago" in the row's status pill, a "Follow-up due" note when `isFollowUpDue`, and
    "You applied to <company> 27 days ago" on the job page. The run line reads the daily runs only (freelance runs keep
    their own line on Freelance).

/**
 * Structural queries over the dashboard's rendered HTML (UX upgrade A0), for tests that must survive markup changes.
 * No parser dependency: the dashboard's own HTML is regular (every non-void element closed, attributes double-quoted,
 * values escaped by `html`), and these helpers rely on exactly that. Security and escaping tests keep exact strings.
 */
const NAMED: Readonly<Record<string, string>> = { amp: '&', lt: '<', gt: '>', quot: '"', apos: "'" };
const VOID = new Set(['area', 'base', 'br', 'col', 'embed', 'hr', 'img', 'input', 'link', 'meta', 'source', 'track', 'wbr']);
const escapeRe = (s: string): string => s.replace(/[.*+?^${}()|[\]\\]/g, '\\$&');

export function decode(s: string): string {
  return s.replace(/&(#x[0-9a-fA-F]+|#\d+|[a-z]+);/g, (m, e: string) =>
    e.startsWith('#x') ? String.fromCodePoint(Number.parseInt(e.slice(2), 16)) : e.startsWith('#') ? String.fromCodePoint(Number(e.slice(1))) : (NAMED[e] ?? m),
  );
}

/** The text a reader gets: scripts and styles dropped, every tag a space, entities decoded, whitespace collapsed. */
export function textOf(html: string): string {
  return decode(html.replace(/<(script|style)\b[\s\S]*?<\/\1>/gi, ' ').replace(/<[^>]*>/g, ' ')).replace(/\s+/g, ' ').replace(/ ([,.;:)])/g, '$1').trim();
}

/** The element that starts at `start` (a `<tag` there), through its matching close tag. */
export function blockOf(html: string, start: number): string {
  const open = /^<([a-z][a-z0-9]*)\b[^>]*>/i.exec(html.slice(start));
  if (open === null) throw new Error(`blockOf: no element at ${start}`);
  const tag = (open[1] as string).toLowerCase();
  if (VOID.has(tag)) return open[0];
  const re = new RegExp(`<(/?)${tag}\\b[^>]*>`, 'gi');
  re.lastIndex = start;
  let depth = 0;
  for (let m = re.exec(html); m !== null; m = re.exec(html)) {
    depth += m[1] === '/' ? -1 : 1;
    if (depth === 0) return html.slice(start, m.index + m[0].length);
  }
  throw new Error(`blockOf: <${tag}> at ${start} is never closed`);
}

/** Every element with attribute `attr` (equal to `value` when given), in document order. */
export function elementsWith(html: string, attr: string, value?: string): string[] {
  const re = new RegExp(`<[a-z][a-z0-9]*\\b[^>]*\\s${escapeRe(attr)}="${value === undefined ? '[^"]*' : escapeRe(value)}"[^>]*>`, 'gi');
  return [...html.matchAll(re)].map((m) => blockOf(html, m.index));
}

export function rowOf(html: string, attr: string, key: string): string {
  const found = elementsWith(html, attr, key);
  if (found.length !== 1) throw new Error(`rowOf: expected one element with ${attr}="${key}", found ${found.length}`);
  return found[0] as string;
}

/** The attributes of the first tag of `el`, values decoded. */
export function attrsOf(el: string): Record<string, string> {
  const tag = /^<[a-z][a-z0-9]*\b([^>]*)>/i.exec(el)?.[1] ?? '';
  return Object.fromEntries([...tag.matchAll(/\s([a-z][a-z0-9:-]*)(?:="([^"]*)")?/gi)].map((m) => [m[1] as string, decode(m[2] ?? '')]));
}

export function linksOf(html: string): { href: string; text: string; attrs: Record<string, string> }[] {
  return elementsWith(html, 'href').filter((e) => /^<a\b/i.test(e)).map((a) => {
    const attrs = attrsOf(a);
    return { href: attrs['href'] ?? '', text: textOf(a), attrs };
  });
}

/** Snapshot folders are read-only (0555); make them writable again so the temp home can be removed. */
export function removeWebHome(home: string): void {
  const walk = (d: string): void => {
    for (const e of readdirSync(d, { withFileTypes: true })) {
      if (e.isDirectory() && !e.isSymbolicLink()) {
        chmodSync(join(d, e.name), 0o755);
        walk(join(d, e.name));
      }
    }
  };
  if (existsSync(home)) walk(home);
  rmSync(home, { recursive: true, force: true });
}

import { existsSync } from 'node:fs';
import { chromium, type Browser } from 'playwright';

/**
 * Real-browser suites (UX upgrade A0, amendment 1): a missing or broken Chromium FAILS the suite. Skipping happens only
 * when the person running the tests says so with JOBPILOT_ALLOW_NO_BROWSER=1, and it is printed.
 */
export const ALLOW_NO_BROWSER_ENV = 'JOBPILOT_ALLOW_NO_BROWSER';
const HINT = `Install it with "node node_modules/playwright/cli.js install chromium", or set ${ALLOW_NO_BROWSER_ENV}=1 to skip on purpose.`;
const allowed = (env: NodeJS.ProcessEnv): boolean => env[ALLOW_NO_BROWSER_ENV] === '1';

export async function launchBrowser(o: { launch?: () => Promise<Browser>; env?: NodeJS.ProcessEnv } = {}): Promise<Browser | undefined> {
  const env = o.env ?? process.env;
  try {
    return await (o.launch ?? (() => chromium.launch()))();
  } catch (e) {
    const why = e instanceof Error ? e.message : String(e);
    if (allowed(env)) {
      console.warn(`[browser] Chromium could not start; skipping on purpose (${ALLOW_NO_BROWSER_ENV}=1): ${why}`);
      return undefined;
    }
    throw new Error(`Chromium is required for this suite and could not start: ${why}\n${HINT}`);
  }
}

export function browserInstalled(o: { executable?: () => string; env?: NodeJS.ProcessEnv } = {}): boolean {
  const path = (o.executable ?? (() => chromium.executablePath()))();
  if (existsSync(path)) return true;
  if (allowed(o.env ?? process.env)) {
    console.warn(`[browser] no Chromium at ${path}; skipping on purpose (${ALLOW_NO_BROWSER_ENV}=1)`);
    return false;
  }
  throw new Error(`Chromium is required for this suite and is not installed at ${path}.\n${HINT}`);
}

```ts
/**
 * The daily loop's shared rules (UX spec U9), in ONE place: what "To decide" means and when a follow-up is due. The
 * store's SQL (`listJobsPage`) implements the same predicate and is pinned to `isToDecideFrom` by
 * tests/app/jobs-page.test.ts; Today and the nav counts (Phase B) call these too. IST calendar dates throughout.
 */
export const TO_DECIDE_DAYS = 7;
export const FOLLOW_UP_DAYS = 5;
/** Eligible (pay at or above the minimum, or not listed) or check first. */
export const DECIDE_BANDS: readonly string[] = ['disclosed', 'undisclosed', 'review'];

const IST_MS = 330 * 60_000;
const DAY_MS = 86_400_000;

export const istDay = (iso: string): string => new Date(Date.parse(iso) + IST_MS).toISOString().slice(0, 10);
export const addDays = (day: string, n: number): string => new Date(Date.parse(`${day}T00:00:00Z`) + n * DAY_MS).toISOString().slice(0, 10);

/** IST midnight, TO_DECIDE_DAYS - 1 days before today (IST), as a UTC instant. */
export function toDecideFrom(now: string): string {
  return new Date(Date.parse(`${addDays(istDay(now), -(TO_DECIDE_DAYS - 1))}T00:00:00Z`) - IST_MS).toISOString();
}

export function isToDecideFrom(j: { readonly status: string; readonly band: string; readonly firstSeen: string }, fromIso: string): boolean {
  return j.status === 'new' && DECIDE_BANDS.includes(j.band) && Date.parse(j.firstSeen) >= Date.parse(fromIso);
}

export const isToDecide = (j: { readonly status: string; readonly band: string; readonly firstSeen: string }, now: string): boolean => isToDecideFrom(j, toDecideFrom(now));

/** `due = next_followup ?? applied_at + 5 d` (IST dates). `nextFollowup` is null until B7 adds the column. */
export function followUpDue(appliedAt: string, nextFollowup: string | null): string {
  return nextFollowup ?? addDays(istDay(appliedAt), FOLLOW_UP_DAYS);
}

export function isFollowUpDue(appliedAt: string | null, nextFollowup: string | null, now: string): boolean {
  return appliedAt !== null && followUpDue(appliedAt, nextFollowup) <= istDay(now);
}
```

/** Parts joined by a middle dot; empty parts are dropped, so a separator never dangles ("GitLab · · via …", A6). */
export function meta(parts: readonly (Html | string | null | undefined | false)[]): Html {
  const kept = parts.filter((p): p is Html | string => (typeof p === 'string' ? p.trim() !== '' : p instanceof Html && p.value.trim() !== ''));
  return html`${kept.map((p, i) => html`${i > 0 ? html`<span class="sep" aria-hidden="true">·</span>` : ''}${typeof p === 'string' ? html`<span>${p}</span>` : p}`)}`;
}

export interface Exception {
  readonly label: string;
  readonly tone: Tone;
}

/**
 * A5: the one non-default state a list row shows, first match wins (plan decision 11). A missing pill means "normal":
 * To do, documents ready and pay at or above the minimum never get one. Colours (amendment 6): blocked is critical,
 * "you decide" is warn, everything else neutral or muted.
 */
export function rowException(j: Pick<JobView, 'docsState' | 'verdict' | 'notes' | 'band'>): Exception | null {
  if (j.docsState === 'blocked') return { label: 'Documents blocked', tone: 'critical' };
  if (j.docsState === 'stale') return { label: 'Documents out of date', tone: 'warn' };
  if (j.docsState === 'missing') return { label: 'Documents missing', tone: 'warn' };
  if (j.verdict === 'review') return { label: 'Check before applying', tone: 'warn' };
  if (j.notes.includes(NOTE_B2B)) return { label: 'Contract (B2B)', tone: 'neutral' };
  const office = j.notes.find((n) => n.startsWith(NOTE_OFFICE_PREFIX));
  if (office !== undefined) return { label: `Office: ${office.slice(NOTE_OFFICE_PREFIX.length)}`, tone: 'neutral' };
  if (j.band === 'undisclosed') return { label: 'Pay not listed', tone: 'neutral' };
  if (j.band === 'below-floor') return { label: 'Pay under your minimum', tone: 'muted' };
  if (j.band === 'rejected') return { label: 'Not a match', tone: 'muted' };
  return null;
}

(function () {
  'use strict';
  var lastId = null;
  var targetId = null;
  document.addEventListener('htmx:beforeRequest', function (e) {
    var a = document.activeElement;
    lastId = a && a.id ? a.id : null;
    var t = e.detail && e.detail.target;
    targetId = t && t.id ? t.id : null;
